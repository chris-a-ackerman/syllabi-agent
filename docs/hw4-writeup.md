## 1. Task and service

**Service offered** ([offer](https://canvas.mit.edu/courses/40577/discussion_topics/449948#entry-232462), posted Oct 12, 14:41 ET): syllabus to calendar and workload estimate. A classmate's agent replies to the offer with 500 to 12,000 characters of syllabus text. The agent replies with a table of dated events, an iCalendar block generated by code, and an hours-per-week estimate. Every event quotes the syllabus line it came from, and code drops any event whose quote is not in the text verbatim, so the requester can check each date.

**Task delegated:** unit tests for `control_state()`, the function (a 15-line module) that reads the course team's control line and decides whether the agent may write at all. It is small, self-contained and safety-critical, so independent tests are useful and can be checked mechanically: they must pass on the real function and fail on two deliberately broken versions.

**Provider choice.** Each cycle a model call ranks every untried offer the agent has read (fit 0 to 3 against the need "can write Python unit tests, or review/test code; stdlib Python; will return a file I can run") and the agent replies to the best one with fit 2 or more (1 or more after 3 cycles with no fit). No partner is hard-coded; a provider that times out, declines or fails is never asked again.

## 2. Technical setup

- **Harness:** a Python driver, `scripts/hw4-cycle.py`, on GitHub Actions (`.github/workflows/hw4-forum.yml`). One run is one cycle: read the forum, classify new entries, post the offer once, serve one job, check one reply to our request, choose a provider and send a request.
- **Model:** `claude-sonnet-5-5` through the Anthropic Messages API, with structured JSON output, for classification, provider ranking, answering a provider's question and the syllabus extraction. Every check and every decision to post is code, not the model.
- **Canvas:** the HW3 forum tool (`workspace/skills/forum/scripts/forum.py`) with my own Canvas token, kept as a GitHub Actions secret. It reads the HW4 topic and posts replies through the Discussions API.
- **Schedule:** every 2 hours. GitHub's cron fires unreliably, so a scheduled Claude Code cloud routine also starts the workflow every 2 hours unless a run started in the last 45 minutes.
- **Memory:** `state/` is committed back to `main` after every run: entries already read, own posts, the open request and its deadline, providers tried, every ranking and every verdict. The next run starts from it, so replies are handled without me relaying messages and a request is never sent twice.

## 3. Results and verification

The agent checks a delivery itself, in a Docker sandbox with no network, a read-only file system, 512 MB, 60 s and no secrets in its environment: **(static)** the file parses, has a `unittest.TestCase` with 3+ tests and imports only the standard library, with no file, network or subprocess use; **(correct)** every test passes against the real function; **(m1)** at least one fails against a mutant that reports PAUSED as RUNNING; **(m2)** at least one fails against a mutant that skips whitespace stripping and upper-casing. All pass: accept and tip. A failure: one correction request quoting the failing output (+12 h), then reject.

## 6. Safety controls

- **Credentials:** the Canvas token and API key are GitHub secrets, never printed (no `set -x`, no environment dumps); `forum.py` scrubs their values from everything it writes or posts. Delivered tests run in a child process with a fresh environment, so secrets never reach peer code.
- **Untrusted input:** peer text is capped and wrapped in random-nonce delimiters, and every prompt says it is data; the model's answers are schema-constrained and re-checked by code (an offer number must name a real candidate). The agent never runs peer instructions; peer code runs only in the sandbox in §3.
- **Bounded tools and spending:** at most 2 posts per cycle, small model calls at low effort, a 20-minute job timeout, and runs never overlap.
- **Forum control and write limit:** before every write the agent reads the control line and writes only on `COURSE-TEAM CONTROL: RUNNING`; at most 3 write attempts per rolling hour, retries included.
- **Verified, de-duplicated posts:** every post is read back; an uncertain write is reconciled against the thread before any retry, and a text hash blocks duplicates.
- **Stopping:** 3 consecutive failures or a rejected token writes a halt file that blocks all posting until a human removes it.
